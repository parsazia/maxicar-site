# سیستم قیمت‌گذاری ماکسیکار بر پایه درهم

وضعیت: مشخصات اجرایی برای پیاده‌سازی و آزمون در محیط آزمایشی؛ هیچ قیمتی در فروشگاه اصلی تغییر داده نمی‌شود.

## هدف
مدیر قیمت پایه هر محصول را به درهم وارد می‌کند. سیستم نرخ روز درهم را از TGJU می‌خواند، قیمت فروش را به تومان محاسبه می‌کند و رو به بالا به نزدیک‌ترین مضرب ۵۰٬۰۰۰ تومان گرد می‌کند. عملیات قیمت‌گذاری هنگام درخواست مدیر اجرا می‌شود، نه روزانه؛ پیش از اعمال گروهی، پیش‌نمایش و تأیید صریح مدیر الزامی است.

## قواعد محاسبه
1. نرخ درهم از منبع TGJU خوانده می‌شود. اگر نرخ به ریال نمایش داده شده باشد، برای تبدیل به تومان بر ۱۰ تقسیم می‌شود.
2. قیمت پایه درهم مستقل از قیمت فعلی تومان نگهداری می‌شود و با تغییر قیمت فروش بازنویسی نمی‌شود.
3. فرمول:
   - قیمت خام تومان = قیمت پایه درهم × نرخ درهم به تومان
   - قیمت فروش = ceil(قیمت خام تومان / ۵۰٬۰۰۰) × ۵۰٬۰۰۰
4. نمونه‌ها: ۲٬۷۳۰٬۰۰۰ تومان به ۲٬۷۵۰٬۰۰۰ تومان گرد می‌شود؛ ۷٬۳۱۲٬۰۰۰ تومان به ۷٬۳۵۰٬۰۰۰ تومان گرد می‌شود.
5. ورودی‌ها باید عدد مثبت و معتبر باشند؛ محاسبات نباید قیمت صفر، منفی یا مقدار نامعتبر تولید کنند.

## نگهداری داده
- قیمت پایه درهم باید در فیلد اختصاصی محصول نگهداری شود. نام دقیق فیلد در `extra_fields` فقط پس از تأیید ساختار واقعی API انتخاب می‌شود.
- قیمت نهایی فروش در فیلد معمول قیمت محصول (`price`) ذخیره می‌شود.
- گزارش هر اجرا شامل شناسه و نام محصول، قیمت پایه درهم، نرخ استفاده‌شده، زمان دریافت نرخ، قیمت قبلی، قیمت محاسبه‌شده و نتیجه عملیات است.
- کلید API فقط در متغیر محرمانه محیط سرور نگهداری می‌شود و هرگز در مرورگر، کد عمومی یا گزارش‌ها قرار نمی‌گیرد.

## دامنه اعمال
- فقط محصولاتی که قیمت پایه درهم معتبر دارند و وضعیت موجودی آن‌ها صریحاً قابل فروش است پردازش می‌شوند.
- محصول بدون قیمت پایه درهم، محصول ناموجود و محصول با وضعیت موجودی نامشخص تغییر نمی‌کند.
- قیمت محصولات با مبنای غیر درهم دست‌نخورده می‌ماند.
- هیچ تغییر گروهی بدون پیش‌نمایش و تأیید صریح مدیر اعمال نمی‌شود.

## نمایش قیمت در سایت
- برای محصول واجد شرایط، قیمت محاسبه‌شده به تومان نمایش داده می‌شود.
- قیمت پایه درهم به مشتری نمایش داده نمی‌شود.
- محصول بدون قیمت پایه درهم، قیمت دستی فعلی خود را حفظ می‌کند؛ اگر قیمت معتبر ندارد، «استعلام قیمت» نشان داده می‌شود.
- وضعیت ناموجود از داده واقعی فروشگاه خوانده می‌شود و قیمت آن خودکار بازنویسی نمی‌شود.
- اگر TGJU در دسترس نباشد یا نرخ نامعتبر/قدیمی باشد، عملیات متوقف می‌شود و هیچ قیمتی تغییر نمی‌کند.
- گزارش مدیریتی زمان دریافت نرخ و نتایج به‌روزرسانی را ثبت می‌کند.

## جریان اجرایی
1. مدیر قیمت پایه درهم یک یا چند محصول را وارد یا اصلاح می‌کند.
2. مدیر اجرای محاسبه را درخواست می‌کند.
3. سرور نرخ روز TGJU را دریافت و اعتبارسنجی می‌کند.
4. سیستم پیش‌نمایش قیمت قبلی، قیمت پیشنهادی و اختلاف را می‌سازد.
5. مدیر پیش‌نمایش را بررسی و صریحاً تأیید می‌کند.
6. سرور فقط محصولات واجد شرایط را با `PATCH /api/v4/products/{product_id}/` به‌روزرسانی می‌کند.
7. نتیجه هر محصول ثبت و پس از نوشتن، با خواندن مجدد از API تأیید می‌شود.

## موارد الزامی پیش از اتصال نوشتن به فروشگاه
- قالب و زمان به‌روزرسانی نرخ TGJU و انتخاب دقیق نرخ خرید/فروش درهم.
- ساختار واقعی `extra_fields` و قالب پذیرفته‌شده برای نوشتن قیمت محصول در API.
- مقادیر واقعی وضعیت موجودی در API.
- وجود کلید API با دسترسی مناسب در محیط آزمایشی.
- احراز هویت مدیر برای صفحه و مسیرهای قیمت‌گذاری؛ مسیر نوشتن نباید عمومی باشد.
- آزمون خطای نرخ، قطع منبع، محصول ناموجود، محصول بدون قیمت پایه، خطای API و گردکردن.

## معیار پذیرش
- گردکردن همیشه رو به بالا و با مضرب ۵۰٬۰۰۰ تومان است.
- محصول فاقد قیمت پایه درهم یا فاقد موجودی تأییدشده تغییر نمی‌کند.
- هیچ قیمت گروهی بدون تأیید مدیر اعمال نمی‌شود.
- کلید API سمت مشتری قرار نمی‌گیرد.
- قیمت جدید از API بازخوانی و تأیید می‌شود.
- فقط نسخه آزمایشی تغییر می‌کند؛ دامنه فعال `maxicar.ir` دست‌نخورده می‌ماند.
